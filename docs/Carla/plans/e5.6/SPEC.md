# E5.6 Route Summary (LLM): Spec

Source: `docs/Carla/M5_GUIDE.md` Part 10, `docs/PLAN.md` E5.6, ARCHITECTURE §7.5.

## Goal

A plain-language summary of at most two sentences above the route options, like a maps app. It is generated by an LLM through OpenRouter, and any summary with a number that isn't in the route data is replaced by a deterministic template.

## Stories (PLAN.md)

- Call OpenRouter (`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`) to generate a two-sentence summary from the structured route data.
- Reject any summary whose numbers don't match the data, and fall back to a template.

## Safety contract

1. The LLM sees only a facts table derived from a contracts v4.0 `route-response`.
2. Every number in the output (`\d+(?::\d\d)?(?:\.\d+)?`) must be in the allowed set. Leading zeros are tolerated.
3. The output is rejected (and the template used) when any of these hold:
   - It contains a number that isn't allowed.
   - It is empty.
   - It has more than 2 sentences.
   - It is longer than 300 characters.
   - The API call raised an exception.
4. The template always passes the number check.
5. The LLM never influences ranking or routing.

## Module: `summary/llm.py`

- `SYSTEM_PROMPT`: at most two short sentences, only the given facts, prefer minutes, and say why option 1 is recommended.
- `Facts(lines, allowed)`.
- `facts_from_response(response, names=None)` builds one line per route: rank, label, flying minutes, wait minutes, traffic, bunching risk %, destination name, arrival HH:MM and the p10–p90 window, and the reason. The allowed set contains:
  - each route's rank, minutes, wait, minutes + wait, and risk
  - the arrival times as HH:MM, also with the leading zero stripped
  - numbers found in place names and reasons
  - positive pairwise differences of (minutes + wait)
  - the route count
- `check_numbers(text, facts) -> list[str]`: the offending numbers.
- `template_summary(response, names=None)`: `"Fastest route: about {total} min to {place}, {traffic} traffic."`, plus `" The next option takes {diff} min longer."` or `"... about as long."`. With no routes it returns `"No route is available right now."`.
- `call_llm(facts, timeout_s=20)`:
  - POSTs `{base}/chat/completions` (OpenAI-compatible) with temperature 0.2, max_tokens 120, a Bearer key and `X-Title: AeroLink`.
  - `LLM_BASE_URL` defaults to `https://openrouter.ai/api/v1`.
  - Raises when `LLM_MODEL` or `LLM_API_KEY` is unset.
- `Summary(text, source: "llm"|"template", rejected=None, bad_numbers=())`.
- `summarize(response, names=None, llm=call_llm) -> Summary`: never raises.
- `iso(base, seconds)` helper.

## Evaluation: `summary/evaluate.py`

```
uv run python -m aerolink.summary.evaluate [--cases 50] [--seed 42] [--template-only] [--network F] [--out F]
```

- Builds `--cases` responses:
  - Random origin/destination pairs, 30% medical.
  - Uses the `A1Advisor` with `cv` ETAs and `to_response(options, network, t0)` (the subset of route-response fields the summary uses).
- Exits with 1 when the environment variables are missing and `--template-only` isn't set.
- Output `backend/eval-results/summary-e5.6.json` contains:
  - `model`, `cases`, `llm_pass_rate`
  - `rejected_number_mismatch`, `rejected_other`, `api_errors`
  - `templates_pass_number_check`
  - `mismatched_numbers_shown_to_users: 0`
  - per-case `results` (source, summary, rejected, bad_numbers, facts)

## Tests: `tests/test_e56_summary.py` (5 tests, no API key)

They use `contracts/examples/route-response/valid/ok-two-options.json`:

- The allowed set includes 19, 15:19 and 3, and invented numbers are flagged.
- A good LLM text is used (`source == "llm"`).
- A wrong number falls back to the template, which passes the check.
- An API error falls back to the template.
- A `--template-only` run with 5 cases has `templates_pass_number_check is True`.

## Configuration and secrets

- `.env.example` already has `LLM_BASE_URL`, `LLM_MODEL` and `LLM_API_KEY`. No change is needed.
- The key is only ever exported in the shell or stored as a Codespaces secret. It must never appear in a file, commit, PR or log.

## Acceptance criteria

1. No summary with a mismatched number reaches a user. This is enforced by the `summarize` contract and proven by the tests.
2. The pass rate is reported in `eval-results/summary-e5.6.json` from a real run of 50 cases with a named `LLM_MODEL`.
3. Tests pass (5), and ruff and ty are clean.
